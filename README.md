# omp-auto-loop

Autonomous loop extension for the [omp/pi coding agent](https://github.com/oh-my-pi),
vendored out of `nixos-config` (`modules/home/omp/auto-loop`). It ports the
internal autonomous runtime of [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)
(`core/autonomous.ts`, `goals.ts`, `cron-jobs.ts`), with the settle-gate
design originating from [DraconDev/opencode-auto-continue](https://github.com/DraconDev/opencode-auto-continue).

## Architecture

The omp harness loads extensions through a `PI_CONFIG_FILES` settings
overlay: a YAML file whose `extensions` array lists entry files that jiti
imports at session start. The overlay is generated by the home-manager
module in [`nix/module.nix`](nix/module.nix) via the harness in nixos-config
(`modules/home/omp/default.nix`), which appends
`config.local.omp.autoLoop.extensionEntries` to its single `extensions`
array — omp deep-merges overlay objects but **replaces** arrays, so there
must be exactly one overlay setting `extensions`.

The extension is delivered as a **directory copy**: the entry
`extension/auto-loop.ts` imports `./lib/*.ts` relatively, so the directory
(not the bare file) must be what lives in the store. Interpolating a single
file strands it at a store root where `./lib/` cannot resolve, and the
extension then fails to load with no error until a session tries to
continue. `test/package.test.ts` asserts this shape.

```
extension/
  auto-loop.ts    entry: budgeted continuation cycle, goal tool, canvas lifecycle
  imp-bridge.ts   standalone session_stop → imp board notifier (optional)
  lib/
    core.ts         cycle state machine, budgets, settle/continue decision
    gates.ts        verifier gates — termination authority when enabled
    observation.ts  event projection to graph.lines
    resume.ts       post-compaction cycle resume
    ports.ts        fs/exec/git port interfaces
    canvas.ts       jump-cannon canvas lifecycle
    commands.ts     /autoloop slash command + config.json reader
```

### Loop semantics

- **Budgets**: each user input starts a cycle with 3 continuations and a
  30-minute wall-clock timeout (prime-agent defaults).
- **Settles keep working**: when the model tries to stop, open questions
  are assumed-and-verified and the loop continues until gates pass, the
  model reports `AUTOLOOP:DONE`, or a cap trips.
- **Gates**: `OMP_AUTO_LOOP_GATES` (JSON array of verifier commands) — when
  set, gates are the termination authority, retried up to
  `OMP_AUTO_LOOP_GATE_RETRIES` with `OMP_AUTO_LOOP_GATE_TIMEOUT_MS` per
  attempt.
- **Goal tool**: a model-driven tool arms a goal; an idle heartbeat keeps
  nudging the session while a goal is active.
- **Slash command**: `/autoloop` arms/disarms the goal loop from chat.
- **Env vars**: `OMP_AUTO_LOOP_MAX_CONTINUATIONS`,
  `OMP_AUTO_LOOP_TIMEOUT_MS`, `OMP_AUTO_LOOP_GATES`,
  `OMP_AUTO_LOOP_GATE_RETRIES`, `OMP_AUTO_LOOP_GATE_TIMEOUT_MS`,
  `OMP_AUTO_LOOP_HEARTBEAT_MS`, `OMP_AUTO_LOOP_DISABLE` — set them in the
  harness's `defaultEnv`.

### Jump-cannon canvas

The loop's visualization: jump-cannon's native `graph-api` binary (flake
input, crane-built) watches `~/.local/state/omp-auto-loop/graph.lines` —
the event projection the extension appends on every cycle event — and
serves it as a live graph (the OMP Auto-Loop Topos). The module deploys it
as the launchd agent `local.omp-auto-loop-jump-cannon` (Darwin):

- `jumpCannon.lifecycle = "omp"` (default): the agent is loaded but idle;
  the extension starts it with the first interactive omp session and stops
  it after the last one exits. One-shot `omp -p` runs never start it. The
  extension discovers the agent label through
  `~/.config/omp-auto-loop/canvas-agent`.
- `jumpCannon.lifecycle = "always"`: launchd `RunAtLoad` + `KeepAlive`
  from login.
- The watcher re-imports on every write; no periodic rescan (each rescan
  publishes a new graph revision and re-lays out the canvas even for an
  unchanged file).

### Imp bridge

`extension/imp-bridge.ts` is a **standalone** extension (it shares nothing
with auto-loop's runtime) that posts a one-line session summary to the imp
agent board when a session stops: `POST {impBridge.url}/api/rooms/{room}/messages`.
Delivery is fire-and-forget — an in-memory queue (max 50, drop-oldest),
exponential backoff (500 ms base, max 5 attempts per message), then the
message is dropped; the `session_stop` path never blocks and the bridge
never throws. It reads the same `~/.config/omp-auto-loop/config.json`
(`impBridge.enable` must be exactly `true`).

## Configuration

The module emits `~/.config/omp-auto-loop/config.json`:

```json
{
  "version": 1,
  "dashboardPort": 8799,
  "impBridge": {
    "enable": false,
    "url": "http://127.0.0.1:4010",
    "room": "kitchen"
  }
}
```

Options under `local.omp.autoLoop`:

| Option | Default | Purpose |
| --- | --- | --- |
| `enable` | `true` | Load the extension. |
| `jumpCannon.enable` | `true` | Deploy the canvas launchd agent (Darwin). |
| `jumpCannon.port` | `8799` | Loopback port for graph-api. |
| `jumpCannon.lifecycle` | `"omp"` | `"omp"` or `"always"`. |
| `impBridge.enable` | `false` | Also register `imp-bridge.ts`. |
| `impBridge.url` | `http://127.0.0.1:4010` | Imp board base URL. |
| `impBridge.room` | `"kitchen"` | Imp board room. |
| `extensionEntries` | *(read-only)* | Store paths of the extension entries, for the harness overlay. |

## Usage

In the consumer flake (nixos-config):

```nix
# flake.nix
{
  inputs.omp-auto-loop.url = "github:ocasazza/omp-auto-loop";
}
```

Import the module by attribute (the module's `inputs` specialArg must carry
`jump-cannon`, which nixos-config's home-manager tree already passes):

```nix
imports = [ inputs.omp-auto-loop.hmModules.default ];
```

or by path:

```nix
imports = [ "${inputs.omp-auto-loop}/nix/module.nix" ];
```

Then register the entries in the omp harness's PI_CONFIG_FILES overlay:

```nix
extensions = ... ++ lib.optionals cfg.autoLoop.enable cfg.autoLoop.extensionEntries;
```
